# Product requirements

Store Markdown product requirements here. Together, these documents should be
complete enough for someone to rebuild the product: its purpose, users, behavior,
and constraints should be understandable without reverse-engineering the code.

Organize documents by product area or capability with descriptive filenames.
Capture the problem, intended users, scope and exclusions, user flows, expected
behavior, edge cases, acceptance criteria, and relevant constraints. Make open
questions explicit and link related requirements, decisions, and artifacts.

Keep requirements current as the product evolves, and distinguish proposed
behavior from accepted requirements. Use `wrk` for implementation tasks and the
wiki for instructions on operating or developing the product.
