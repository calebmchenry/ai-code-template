# Project documentation

Keep durable project knowledge here so a new teammate or agent can find the
context needed to do the work. Start with the [wiki index](wiki/index.md) for
practical guidance.

| Directory | What belongs here |
| --- | --- |
| [decisions/](decisions/README.md) | Decisions, their context, the alternatives considered, and the reasons for the choice. |
| [artifacts/](artifacts/README.md) | Screenshots, mockups, architecture diagrams, and other files worth preserving and linking to. |
| [prds/](prds/README.md) | Product requirements: what the product must do, for whom, and how to tell it works. |
| [wiki/](wiki/README.md) | How to work on the project: setup, commands, workflows, troubleshooting, and project knowledge. |

Use relative links to connect related requirements, decisions, guides, and
artifacts. Update documentation when the product or workflow changes, and add
new wiki pages to [wiki/index.md](wiki/index.md).

Track tasks and their status in `wrk`; link tickets to durable documentation
instead of using docs as a second backlog.
