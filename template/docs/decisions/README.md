# Decisions

Store Markdown records of decisions that future contributors will need to
understand: architecture, technology choices, product tradeoffs, and working
conventions.

Give each record a descriptive filename, such as `0001-use-postgres.md`. Include
the date, status, context, decision, alternatives considered, and consequences.
Link to relevant requirements, tickets, and supporting artifacts.

When a decision changes, mark the earlier record as superseded and link to its
replacement. Preserve the reasoning so readers can understand how the project
arrived at its current approach.
